CSSコーディング標準：余白・レスポンシブ・単位ルール

方針：8pxグリッドを基準に、再利用可能なデザイントークンとレスポンシブ設計を優先する。
注意：数値は初期値。既存デザインやブランドガイドラインが既にある場合はそちらを優先し、理由なく全体を作り直さない。

1. 基本原則
1. 同じ役割の要素には、同じデザイントークンを再利用する。
2. 余白は原則として4px刻み、主要な余白は8px刻みを使う。
3. 8pxグリッドはガイドラインであり、絶対規則ではない。1pxの境界線、アイコンの視覚補正、文字組みなどは例外を許容する。
4. 既存のCSS、テーマ、デザインシステムにトークンがある場合は、既存の命名と値を優先する。
5. 同じ目的の値をページごとに重複定義しない。共通値はCSSカスタムプロパティへ集約する。
6. レスポンシブ対応は、デバイス名ではなくコンテンツが自然に収まらなくなる幅を基準にする。
7. レイアウトを成立させるために、固定幅・固定高をむやみに増やさない。
8. !important早もおえない時のみ使い、過剰なセレクタ詳細度、同じ宣言の重複を避ける。
9. 既存実装を変更する前に、該当コンポーネントのHTML構造、親要素、既存トークン、テーマの制約を確認する。
10. 実装後は少なくともモバイル・中間幅・デスクトップで確認し、横スクロール、文字切れ、重なり、過大な空白を検証する。
11.デスクトップでのレスポンシブ画像の16:9幅の比率を考慮する
12.CSSのファイルは規則性を持って混乱の少ない運用しやすい形にまとめる

2. 余白スケール
推奨する基本スケール：

  Token              値 主な用途
  --space-1       4px 微調整、アイコンと文字の間隔
  --space-2       8px 密接した要素、ラベルと入力欄
  --space-3      12px コンパクトな内部余白
  --space-4      16px 基本的なカード内余白
  --space-5      24px 関連要素・小グループ間
  --space-6      32px コンポーネント間
  --space-7      40px コンテンツグループ間
  --space-8      48px 小〜中規模セクション間
  --space-9      64px 標準的なデスクトップのセクション間
  --space-10     80px 大きなセクション間
  --space-11     96px ヒーローや大きな区切り

運用ルール：
- カード内部：通常16〜24px。
- 関連コンテンツの間：通常24〜32px。
- セクション間：モバイル40〜48px、デスクトップ64〜96pxを初期値とする。
- ページ左右の余白は、セクション上下の余白と別トークンで管理する。
- 余白を選ぶときは、まず既存トークンから選ぶ。新しい値を追加するのは、既存値では意図を表現できない場合に限る。
- 余白を8pxの倍数にするために、視覚的に不自然な配置を受け入れない。
3. CSSカスタムプロパティの例
:root {
  /* Spacing */
  --space-1: 0.25rem;  /* 4px */
  --space-2: 0.5rem;   /* 8px */
  --space-3: 0.75rem;  /* 12px */
  --space-4: 1rem;     /* 16px */
  --space-5: 1.5rem;   /* 24px */
  --space-6: 2rem;     /* 32px */
  --space-7: 2.5rem;   /* 40px */
  --space-8: 3rem;     /* 48px */
  --space-9: 4rem;     /* 64px */
  --space-10: 5rem;    /* 80px */
  --space-11: 6rem;    /* 96px */

  /* Layout */
  --page-gutter: 1rem;
  --content-max: 75rem; /* 1200px */
  --section-space: 3rem;

  /* Typography */
  --text-sm: 0.875rem;
  --text-base: 1rem;
  --text-lg: 1.125rem;
  --text-xl: 1.25rem;
  --text-2xl: 1.5rem;
}

@media (min-width: 48rem) {
  :root {
    --page-gutter: 2rem;
    --section-space: 4rem;
  }
}

@media (min-width: 64rem) {
  :root {
    --page-gutter: 2.5rem;
    --section-space: 5rem;
  }
}

.page-section {
  padding-block: var(--section-space);
}

.container {
  width: min(
    calc(100% - var(--page-gutter) * 2),
    var(--content-max)
  );
  margin-inline: auto;
}
1rem = 16pxを前提にした例。ユーザー側のルートフォントサイズを尊重し、ルートの`font-size`を固定してremの拡大縮小を無効化しない。
4. px / rem / em / % / vw / vh / svh / dvh の使い分け
  単位                    主な用途                                                       注意点
  px                    1pxの境界線、細かい視覚補正、厳密なピクセル調整                大きな余白や文字サイズをpxだけで固定しない

  rem                   文字サイズ、余白、コンテナの基準値                             ユーザーの文字サイズ設定への適応に向く

  em                    文字サイズに連動するアイコン・内部余白など                     親子で倍率が重なると予想外の値になりやすい

  %                     親要素に対する幅、画像の幅など                                 高さの%は包含ブロックの高さに左右される

  vw / vh             ビューポートに連動する装飾や特殊レイアウト                     モバイルのブラウザUI、極端な画面幅に注意

  svh                   モバイルでブラウザUIが表示された小さいビューポート基準の高さ   画面内に収めるUIで検討する

  dvh                   ブラウザUIの変化に追従する動的なビューポート高さ               スクロール時に高さが変わり得る

  ch                    テキスト行長の目安（例：`max-width: 65ch`）                    実際の文字幅を厳密に保証する単位ではない
  fr                    CSS Gridの利用可能な空間の配分                                 Gridレイアウト内で使用する

推奨判断
- 余白、文字サイズ、角丸などのデザイントークン：基本的に`rem`。
- 1pxの境界線や必要な精密調整：`px`。
- コンテナ幅：`width: min(100% - gutter, max-width)`のように、相対幅と最大幅を組み合わせる。
- 画像：原則`max-width: 100%; height: auto;`。トリミングが必要な場合は`object-fit: cover`と用途に応じたアスペクト比を使う。
- 長文の行長：`max-width: 60ch`〜`70ch`程度を出発点にする。
- ヒーローの文字サイズ：`clamp()`で最小値・可変値・最大値を指定する。
- 全画面に近いモバイル領域：必要に応じて`min-height: 100svh`または`100dvh`を検討する。単純にすべての高さを`100vh`で固定しない。
- vwを文字サイズに直接使う場合は、狭い画面で小さくなりすぎたり、広い画面で大きくなりすぎたりしないよう`clamp()`を組み合わせる。

5. レスポンシブ・ブレークポイント
以下は開始点の例であり、業界共通の絶対規格ではない。

  用途                                 例
  小さなモバイル                  〜479px
  大きなモバイル               480〜767px
  タブレット・小型ノート      768〜1023px
  デスクトップ               1024〜1279px
  広いデスクトップ               1280px〜


CSSではremを使って定義してもよい。デフォルトのルートサイズが16pxなら、`48rem`は768px、`64rem`は1024pxに相当する。
/* Mobile first */
.product-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: var(--space-5);
}

@media (min-width: 48rem) {
  .product-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (min-width: 64rem) {
  .product-grid {
    grid-template-columns: repeat(3, minmax(0, 1fr));
    gap: var(--space-6);
  }
}
ブレークポイントを追加する前に、Flexbox、Grid、`minmax()`、`auto-fit`、`auto-fill`、`clamp()`で自然に対応できないか確認する。
6. 流用しやすいレスポンシブパターン
流動的な文字サイズ
.hero-title {
  font-size: clamp(2rem, 1.2rem + 2.5vw, 3.5rem);
  line-height: 1.1;
}
clamp(minimum, preferred, maximum)を使い、文字サイズの下限と上限を定める。日本語の見出しでは文字数や改行位置も確認し、必要なら別途ブレークポイントで調整する。
流動的なセクション余白
.page-section {
  padding-block: clamp(2.5rem, 5vw, 6rem);
}
この例はモバイル40px相当からデスクトップ96px相当までを想定する。厳密に段階を制御したい場合は、メディアクエリとトークンを使う。
自動折り返しするカード
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 17rem), 1fr));
  gap: var(--space-5);
}
カードの最小幅はコンテンツに合わせて調整する。商品カードなど列数を明示的に制御したいUIでは、ブレークポイントを使う方が予測しやすいこともある。

7. タイポグラフィと可読性
- 本文は通常`1rem`程度を起点とし、実際のフォント・行長・ブランドに合わせて調整する。
- 本文の`line-height`は一般に`1.5`〜`1.75`程度、見出しは`1.1`〜`1.3`程度を起点にする。
- 日本語は英語より行長や改行の見え方が異なるため、文字サイズだけでなく実際の文章で確認する。
- 見出しに固定の高さを指定して文字切れを起こさない。
- 長い英数字やURLがある場合は、`overflow-wrap: anywhere`などを必要な箇所に適用する。
- letter-spacingは全体に機械的に適用せず、フォントと文字サイズを見て決める。

7.1 日本語ディスプレイ見出しの折り返し（モバイル優先）
英語の単語境界改行とは違い、日本語の見出しは「どこで切るか」がブランドと可読性に直結する。次の3層を組み合わせる。

**層1 — CSSで均等・禁則を整える（全JA見出しに適用）**
```css
html[lang="ja"] h1,
html[lang="ja"] .heading-balanced {
  text-wrap: balance;   /* 2行以上になったとき行長を均す */
  line-break: strict;   /* より厳格な禁則（句読点・開き閉じなど） */
  word-break: normal;
  overflow-wrap: normal;
  white-space: pre-line; /* コピー内の意図的な \n を行分けとして尊重 */
}
```
- `html[lang="ja"]` でスコープし、英語ロケールの見出し挙動は変えない。
- クラス名の例: `.heading-balanced`（セクションh1/h2に付与）。

**層2 — 長いタイトルはコピー側で意図的な改行を入れる**
- 短い見出し（目安4文字前後、例:「料理一覧」）は1行のままにする。無理に `\n` を入れない。
- 長い見出しは意味の切れ目で `\n` を入れる（読点の直後、修飾と本体のあいだ、複合語の境界など）。
- i18nキーに改行を持たせ、表示側は `white-space: pre-line`（または同等）で拾う。
- 例:
  - `海の幸に、\nアジアの気配`
  - `なぜ、\nここに来るのか`
  - `おまかせ\n創作メニュー`

**層3 — 字サイズは既存スケールを維持（任意の縮小はしない）**
- モバイルでも見出しの `text-4xl` など既存トークンはそのまま使う。折り返しは層1・層2で整える。
- どうしても収まらない場合のみ、個別にブレーク位置かレイアウトを見直し、安易に字サイズを下げない。

**運用ルール**
- 翻訳ごとに改行位置を見直す。英→日の機械的な1:1置換で `\n` を持ち込まない。
- 改行位置は「意味の塊」優先。見た目だけの等分割は避ける。
- 8文字前後でも自然に1行で収まるなら `\n` は入れない（例:「カスタマーレビュー」「料理一覧」）。
- 実装後は実機幅（〜375px）で、1行止まり／意図通り2行／禁則違反がないかを確認する。

8. レイアウト・アクセシビリティ
- box-sizing: border-boxを基本にする。
- 横方向のはみ出しを隠すためだけに`overflow-x: hidden`を追加しない。原因となる幅、Grid、画像、絶対配置を調査する。
- コンテンツを押し込むための固定高を避け、必要なら`min-height`を使う。
- ボタンなどの操作領域は、視認性と操作性を確保する。タッチ操作を前提にする場合は44px程度以上の高さ・幅を一つの目安にする。
- :focus-visibleなどキーボード操作時のフォーカス表示を消さない。
- 動きを加える場合は`prefers-reduced-motion`を考慮する。
- 色、余白、文字サイズだけで情報の意味を伝えない。
9. AIコーディングエージェントへの指示テンプレート
次の指示を、個別のコーディングプロンプトに添付する。
このプロジェクトでは、添付のCSS標準を共通ルールとして適用してください。
1. まず既存のDOM構造、CSS、テーマの制約、既存のデザイントークンを確認してください。
2. 既存デザインと指示がある場合はそれを優先し、無関係な部分を変更しないでください。
3. 余白は4px刻み・8pxグリッドを基本とし、既存のトークンを優先して再利用してください。8pxの倍数にすること自体を目的にしないでください。
4. モバイルファーストを基本に、コンテンツが破綻する幅を基準としてレスポンシブ対応してください。
5. 文字サイズや余白には`rem`、精密な境界線には`px`、可変サイズには`clamp()`など、用途に適した単位を選んでください。
6. 同じ値の重複を避け、再利用可能な値は既存のCSS変数・テーマ設定へ集約してください。
7. 固定幅・固定高・`!important`を必要以上に使わず、Grid/Flexboxと制約ベースのレイアウトを優先してください。
8. 日本語のディスプレイ見出しは、§7.1に従い`text-wrap: balance` / `line-break: strict`を適用し、長いタイトルのみ意味の切れ目で`\n`を入れてください。短い見出しは1行のままにしてください。
9. 変更後はモバイル・タブレット相当・デスクトップ相当で、横スクロール、重なり、文字切れ、余白の不整合を確認してください。
10. 実装内容、変更ファイル、確認した画面幅、未確認事項を簡潔に報告してください。
11. 既存の仕様とこの標準が衝突する場合は、勝手に大規模変更せず、衝突箇所と選択肢を提示してください。

10. 実装チェックリスト
- [ ] 既存のトークンとコンポーネントを確認した
- [ ] 同じ役割の余白を共通トークンに統一した
- [ ] 4px刻み・8pxグリッドを基本にした（必要な例外は許容）
- [ ] モバイルの左右余白とセクション上下余白を分けて設計した
- [ ] px、`rem`、`%`、`vw`、`vh`などを用途に応じて使い分けた
- [ ] 固定幅・固定高に依存しすぎていない
- [ ] 長いテキスト、翻訳、商品名などでも崩れない
- [ ] 日本語見出しは`text-wrap: balance` + 必要なら意図的な`\n`で確認した
- [ ] 短いJA見出しに不要な改行を入れていない
- [ ] 横スクロール、重なり、文字切れがない
- [ ] キーボードフォーカスとタッチ操作を確認した
- [ ] 変更範囲が必要最小限である
- [ ] 実装後の確認内容と未確認事項を報告した

運用上の最重要ルール
このファイルは、あらゆるサイトを同じ見た目にするための規格ではなく、実装の一貫性を高め、判断のばらつきと手戻りを減らすための共通基準である。

ブランド固有のデザイン、既存テーマ、アクセシビリティ、実際のコンテンツがこの基準より優先される場合がある。例外を設けるときは、理由が説明でき、他の画面でも再利用できるかを確認する
